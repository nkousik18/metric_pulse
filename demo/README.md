# demo/

The static replay site at **https://nkousik18.github.io/metric_pulse/** (`docs/hosting-scope.md`
§6.1–6.3, milestone H1). It shows what MetricPulse actually does without running a server: the
real pipeline and agents are run once, their API responses are saved, and the unchanged SPA plays
them back. Nothing on the site is hand-written or mocked (rule R1).

## Files

| Path | What |
|---|---|
| `record.py` | Drives the real Django views through `django.test.Client` and saves each response to `recordings/`, with `index.json` (request key → file) and `manifest.json` (date, commit, models, prompt hashes, LLM cost, cases). |
| `build.py` | Renders `templates/index.html` with Django's template engine alone, adds the banner, a "Recorded runs" tab and `replay.js`, copies the recordings to `data/`. Output `_site/` (gitignored). |
| `static/replay.js` | Wraps `window.fetch`: every `/api/` call is answered from `data/`; an unrecorded one gets a visible "not recorded" notice and an error, never an invented answer. Replays the Action Agent walk-through in order. |
| `keys.py` | The request-key rules, mirrored in `replay.js`; `tests/test_demo_site.py` runs both on the same inputs. |
| `recordings/` | The committed recordings (~0.8 MB). Regenerate with the command, never hand-edit. |

Published by `.github/workflows/pages.yml` on a push to `main` that touches `demo/` or
`templates/`. Building needs only Django: no secrets, no database, no LLM.

## Commands

```bash
python -m demo.record            # real Groq calls (7, ~$0.003); refuses to run on a dirty tree
python -m demo.record --check    # Q2: re-record the deterministic files, compare with recordings/
python -m demo.build             # -> demo/_site/
python -m http.server -d demo/_site 8001   # then open http://127.0.0.1:8001/
pytest tests/test_demo_site.py -v
```

Re-record on a clean commit, then commit `demo/recordings/` on its own. The banner and manifest
name the commit the recording was made at.

## What is recorded

- **Dashboard:** `/api/metrics/?days=60`; `/api/anomalies/` at all 21 slider stops (1.0–3.0σ);
  `/api/decomposition/` and `/api/narrative/` for the default pair and each of the 60 dates vs the
  day before. Other date pairs show the "not recorded" notice.
- **Pipeline buttons:** both, for each metric. "Run & Send Alert" wrote to a scratch outbox.
  "Run Analysis" on Avg Order Value records a failed run (`pipeline_status: failed`): Olist's
  dimension tables have no `avg_order_value` column (`docs/project/BUG_LOG.md` A4-1).
- **AI investigations:** three real cases labelled in the detection eval, inside the dashboard's
  60-day window: d14 (Golden Case #1, revenue 2018-09-03 vs 08-29, the data-tail case), d04
  (order count 2018-08-25 vs 08-24, an event) and d13 (revenue 2018-08-23 vs 08-22, not an event).
  The "Recorded runs" tab opens each one in the dashboard.
- **Action Agent:** real proposals for the same three cases, then approve → edit → reject → undo,
  all with `live: false`, plus the real 400 for a reject/undo without a reason. The replay only
  accepts the recorded order, reason and params (pre-filled on the highlighted card).
- **Onboarding:** the M6 Superstore classification and `run_cycle` for sales, profit,
  order_quantity and shipping_cost. Needs `onboarding/generated/superstore_sales/` locally.
- **Evals:** the newest ledger row and baseline per eval (`evals/ledger.jsonl`).

## Gotchas

- **Isolation.** `record.py` sets `ACTIONS_DB_PATH`, `CHECKPOINTS_DB_PATH`, `OUTBOX_DIR` and the
  approver token to a scratch directory *before* importing the project (settings are read at
  import), so the real `actions.db`/`outbox/` are never touched. The scratch path is replaced by
  `<scratch>` in the saved JSON, the only change made to any response; a test fails on any
  `/Users/`, `/tmp/` or similar path in `recordings/`.
- **Determinism (Q2).** Everything except investigate, actions and pipeline reproduces
  byte-for-byte, apart from the narrative's "Generated by MetricPulse at <time>" line, which
  `--check` masks.
- **LangSmith links** are in the manifest but not shown: the runs live in a private org.
- **Template anchors.** `build.py` inserts at exact strings that must appear once; if a template
  change moves one, the build fails and names it.
- **The proposals vary run to run** (LLM). The walk-through planner needs one reversible type and
  one editable type among the three; it fails loudly if a run doesn't give that.
